# YIAI 物业 AI 平台｜最终面试演示指南

> 适用版本：`interview-demo-final-20260811`  
> 线上配置：RuntimeRelease `v35`  
> 本文已替代旧 S10-B 演示说明；旧交互和旧架构口径不得继续使用。

最终验收材料：[YIAI 物业 AI 平台｜求职 Demo 最终验收卡](./FINAL-DEMO-ACCEPTANCE-2026-08-11.md)

## 1. 三分钟开场话术（计入总时长）

> 这是我独立完成的 AI 物业平台求职 Demo。它不是简单聊天机器人，而是把 Agent 路由、Skill、RAG、MCP、受控业务写入、Badcase / Golden Set 质量闭环和逐请求成本治理放进同一个可操作产品。我的重点不是堆能力，而是让能力为什么被选择、用了什么依据、是否写入成功以及花了多少钱，都能由用户和产品经理看懂并复核。

这段控制在 30 秒内，并计入下面三分钟总时长。

## 2. 面试前准备

只需提前打开四个页面，不要现场改配置：

1. 业主工作台：保留儿童托管、装修引用、工单 Proposal 三条已有对话；
2. 版本发布：打开当前 v35 与上一版本 Diff；
3. Badcase / Golden Set：打开一条已处理案例和一条人工通过用例；
4. Trace 与成本：默认选择“昨天”，再准备一条正常 B 类 Trace 详情。

检查线上 URL 能打开即可。不要在面试前重新发布 RuntimeRelease、重复确认工单或批量运行 Evaluation。

## 3. 三分钟主演示

全程只切换四个主页面，安排约 2 分 30 秒内容和 30 秒缓冲。不要为了覆盖功能清单而加速乱点。

### 0:00–0:30｜项目介绍

使用第 1 节话术，不操作页面。

### 0:30–1:05｜业主工作台：主链与真实能力

打开儿童托管对话：

- 用户问：`物业提供孩子托管服务吗？`
- 页面显示：B 路、儿童教育 Agent、命中的“孩子托管服务” Skill；
- 口头说明：Router 一次完成业务分类和 Agent 选择，Agent 选定后冻结，再按需使用自身绑定能力。

一句话：**“我让业务归属、处理角色和实际使用的规则都对用户可见。”**

### 1:05–1:35｜版本发布：配置如何真正生效

展示 v35 与上一版本 Diff：

- 管理员在原 Agent 页面勾选/取消系统现有 Skill、RAG、只读 MCP/Tool；
- 保存进入 Draft，发布后才形成新的 RuntimeRelease；
- 旧会话固定旧 Snapshot，新会话采用新版本。

一句话：**“原理上平台支持能力扩展，但演示选择受控入库和热绑定，兼顾灵活性、可解释性和稳定性。”**

面试时只看已有 Diff，不现场发布新版本。

### 1:35–2:05｜Badcase / Golden Set：质量治理闭环

- 自动捕获只生成“疑似问题”，人工新增走同一列表；
- Darwin · Pro 只生成处理建议，不自动改分类、配置或状态；
- Golden Set 运行真实主链，结构结果与回答都由人工做最终 PASS/FAIL。

一句话：**“AI帮助发现和分析问题，但产品负责人保留定性、采用、复测和关闭权。”**

### 2:05–2:30｜Trace 与成本：费用与质量可解释

- 日期统计按 Flash / Pro 展示调用数、Hit、Miss、Output、Total；
- Trace 展示 Router、同一垂直 Agent 的首答/续答等每个物理请求；
- 本次主演示中的普通问答用 Flash，Darwin 深度分析使用 Pro；其他低频深度任务也可按已发布模型策略使用 Pro；
- 页面同时展示减少调用次数、减少无关上下文和保持回答依据的质量边界。

一句话：**“我不是只看总费用，而是能解释每次费用花在哪个节点，以及为什么值得花。”**

### 2:30–3:00｜缓冲与追问

停止操作，留给页面切换、网络延迟或面试官追问。RAG、MCP、受控写入和 C 类隔离放到八分钟扩展演示，不在三分钟里硬塞。

## 4. 八分钟扩展演示

面试官愿意深入时，再补充以下路径：

| 能力 | 正常用户表达 | 应展示的结果 |
|---|---|---|
| A 人工协同 | `我不想继续跟AI聊了，请帮我转接物业工作人员。` | 自然语言直接创建普通 Handoff；不调用垂直 Agent、Skill、RAG、MCP，也不触发物业业务 ActionGateway 写入。默认展示已有 Handoff，不现场新建 |
| B Skill | `物业提供孩子托管服务吗？` | 儿童教育 Agent；按需命中托管 Skill |
| B RAG | `小区装修施工每天允许到几点？周末和节假日有什么不同？` | 物业 Agent；只展示模型声明采用且通过 EvidenceSet ID/类型成员校验的分片。系统不冒充答案语义正确性的最终裁判 |
| B MCP | `帮我查一下我最近提交的报修工单，现在还有多少条没处理完？` | 同一 Agent 调用只读工单 MCP；工具结果不冒充 RAG 引用 |
| B 写入 | `我家厨房水龙头漏水，请帮我报修。` | 信息足够后返回待确认 Proposal；未确认前没有正式工单 |
| C 通用问答 | `什么是系外行星，科学家通常用什么方法发现它们？` | 进入 C 类通用 Agent；可用自身绑定能力，但不能访问物业能力和业务数据 |

若现场发送 B 写入问题，只展示 Proposal，不点击确认。

## 5. 五个容易被追问的解释

### 为什么有些回答是 2 次 Provider 请求，有些是 3 次？

2 次通常是 `Router 1 次 + 垂直 Agent 1 次`。3 次通常是 Agent 在读取 Skill、调用 MCP 或取得工具结果后，由**同一个 Agent**再续答一次。它不是第二个 Agent，也不是重新路由；Trace 会把 Router、同 Agent 首答和续答分别列出。

### “相邻上下文未单独评分”是不是不相关？

不是。Top-K 先选出带分数的命中种子，系统再补同文档相邻分片避免断章取义。相邻分片没有独立检索分数，所以明确展示“未单独评分”，而不是伪造一个分数。

### Token 为什么不能把 Reasoning 再加进 Total？

平台口径是：

- `Input = Hit + Miss`
- `Total = Input + Output`
- Reasoning 是 Output 的组成部分，只单独展示，不再次相加。

### 为什么不现场演示任意插件上传即热插拔？

原理上架构支持扩展，但企业应用更需要来源、版本、权限和回滚可控。当前 Demo 展示的是：能力先受控入库，再通过 Agent 绑定和 RuntimeRelease 热生效。这比为了表演灵活性直接运行未知插件更符合真实交付方式。

### 这个项目距离生产还有什么？

功能设计、运行合同和开发交付说明可以直接交给团队继续生产化；但当前个人 Demo 不声称已经完成企业级权限、租户隔离、并发压测、高可用、合规、安全审计和 SLA。

## 6. 成本优化怎么讲

只讲三类真实存在的设计：

1. **减少请求数量**：Router 一次完成 A/B/C 和 Agent 选择；不再使用独立 Selector、Resolver、Planner、第二套路由或自动换 Agent。
2. **减少装载 Token**：Router 只看最小 Agent 卡；垂直 Agent 只装配自身绑定能力；Skill 按需使用；RAG 只装载相关候选和必要相邻分片。
3. **守住质量边界**：完整会话仍保留；物业事实必须有 Skill、RAG 或真实工具依据；Flash 处理常规高频问题，Pro 用于 Darwin 以及 A/B 等已发布策略允许的低频深度任务。

没有同题实测时，不宣称具体节省百分比；Provider Usage 不完整时，不伪造精确金额。

## 7. 现场异常的最短兜底

- 模型响应慢：停止重复点击，直接打开已有对话和对应 Trace；
- 当天没有统计：切到“昨天”“本周”或自定义日期；
- Proposal 已成功但历史卡仍显示确认：解释幂等保护，展示已有 Receipt，不再点击；
- 当前问题需要付费运行：先告诉面试官会产生一次真实 Provider 请求，再决定是否执行；
- 页面或核心链路不可用：停止现场操作，使用 GitHub 项目说明和已有验收材料，不临时改代码。

## 8. 不要这样表述

- 不说“生产级系统已经完成”；
- 不说“支持任意未知插件无审核实时运行”；
- 不说“Badcase 会自动修好系统”；
- 不把 MCP 结果叫作 RAG 参考资料；
- 不把 Thinking 叫作 Pro 模型；
- 不把平台价格快照叫作 DeepSeek 最终账单；
- 不把单个 Golden Case 通过扩大为所有问题质量都已保证。

## 9. 收尾话术

> 这个项目最能体现我的能力，不是我会调用多少模型，而是我能把 AI 的不确定性拆成产品可控的路由、证据、授权、质量和成本机制；同时我也能单人把产品设计落到真实代码、NAS 部署和可核对的运行证据。它是求职 Demo，不冒充生产系统，但功能设计和验收合同可以直接交给研发团队继续生产化。
