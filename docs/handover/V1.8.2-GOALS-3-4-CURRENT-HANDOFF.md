## 2. 项目定位与目标③④范围

### 2.1 目标③：能力优化闭环

Demo 最小闭环是：运行时失败或业主差评形成 Badcase → 关联原 Trace → 人工/AI 辅助分类与根因假设 → 形成可审核修复草稿 → 人工应用 → 同题复测 → 验证 → 发布观察 → 关闭。AI 专家只能分析和生成草稿，不能自动修改代码或绕过审核。

不在本阶段建设：全自动归因、自动修代码、自动发布、线上流量实验平台、大规模标注系统、完整 RBAC、生产 SLA 与多租户质量治理。

### 2.2 目标④：能力成本治理

Demo 最小闭环是：按 `model/stage/usage_source/price_snapshot/formula` 展示一次调用的成本证据；Provider Usage 不完整时明确显示不可得；用少量可执行策略解释“为什么省、怎样验证、什么时候不能宣称省钱”。

不在本阶段建设：供应商账单对账、基础设施与人工成本全口径 FinOps、自动异常检测、自动模型路由优化、生产预算审批和成本 SLA。

## 5. 当前真实运行架构

```text
聊天请求
  → app/runtime/legacy_chat.py（HTTP/SSE 薄适配）
  → RuntimeCoordinator
  → RuntimeRelease / RunConfigSnapshot
  → Router
  → 垂直 Agent
  → 按需 Skill / RAG / 只读 MCP
  → Citation 校验 / Evaluation 断言
  → Evidence Ledger / Trace / Badcase / Cost
```

受控写入独立于普通咨询：

```text
规则工作流
  → Draft
  → ActionProposal
  → 业主确认（HITL）
  → ActionGateway
  → 内部业务服务
  → ActionReceipt
```

模型可以辅助理解和生成回答，但不能授权写入、不能直接提交业务状态，也不能仅凭文本宣称成功。
