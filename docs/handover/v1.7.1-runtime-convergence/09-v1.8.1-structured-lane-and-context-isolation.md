# 09｜V1.8.1 结构化三路运行时与上下文隔离

> 文档版本：`1.8`。
> 状态：`Active`。
> 生效日期：`2026-07-30`。
> 替代关系：接受 ADR-0008；修订 08 文档中“自然语言直接进入 Router 再选 Agent”的执行顺序，其他 Release、Snapshot、Evidence、ActionGateway、Citation 与 Cost 契约继续有效。

## 1. 变更动因

真实失败 Trace `421abf858b9a4869` 证明：Router 与业务 Agent 共用 Agno 自动历史时，控制 JSON 可能进入业务回答上下文；同时“先让 Router 从全部 Agent 自由选择、再事后纠正”不能证明跨域能力没有越权。

本修订不新增平台或业务能力，只把现有咨询执行顺序收敛为可验证的控制合同。

## 2. 当前批准的咨询执行顺序

```text
自然语言
→ 前置 Handoff 规则
→ LaneDecision
→ Lane 内 Agent 候选集
→ RouteDecision
→ CapabilityDecision
→ 回答或执行合同
→ Trace / RunEvidenceLedger
```

Lane 固定为：

- `A_SAFETY_HANDOFF`：安全风险直接 Handoff，不进入普通 Agent。
- `B_PROPERTY_GOVERNED`：只允许 `domain_scope=property`；物业事实继续受 Evidence、Tool 与 ActionGateway 契约约束。
- `C_ISOLATED_GENERAL`：只允许 `domain_scope=isolated_general`；不得使用物业 Skill、RAG、MCP/Tool 或业务写入。

明确要求人工属于前置 Handoff，可不生成 Lane；否定人工语义继续有效，但安全风险可以覆盖否定。

## 3. 结构化控制对象

`LaneDecision` 至少保存：`lane`、稳定 `reason_code`、`business_intent`、`confidence`、`needs_clarification`、`decision_source`、`matched_signals`、`allowed_domain_scopes`。

`CapabilityDecision` 至少保存：实际 Agent，以及 Skill、RAG、Tool、write、handoff 的 selected/skipped/required 状态和稳定原因。

Schema 非法不得继续自由路由。Router 建议的 Agent 不在 Lane 候选集时，记录 `lane_agent_scope_mismatch` 并使用 Lane 内确定性 fallback。

## 4. 控制面与回答面隔离

- `chat_messages` 是用户可见多轮历史的唯一事实源，只注入最近 5 轮成功可见消息。
- Router 与业务 Agent 关闭 Agno 自动历史，并使用不同阶段 session。
- LaneDecision、候选 Agent、Router Prompt、Router JSON 和 reason 不进入业务 Agent 上下文。
- 当前用户消息只注入一次；Trace 与成本继续关联原业务 session。
- 最终输出若整体符合控制 JSON，记录 `internal_control_payload_leak`，返回受控错误且不自动重试。

## 5. 不变边界

- RuntimeRelease 与新旧会话 Snapshot 合同不变，本次代码修复不发布新 Release。
- Agent/Skill/RAG/MCP 配置、模型价格、成本计算和 ActionGateway 不变。
- 不新增数据库表或字段；LaneDecision 与 CapabilityDecision复用现有 Evidence Ledger JSON。
- T1—T4真实验收仅在无模型反例和回归通过后按顺序各执行一次。

## 6. 回滚

普通 `git revert` 本修订实现提交后仅重建 API；RuntimeRelease 继续指向 v27，历史 Trace 与会话 Snapshot 不改写。
