# 10｜V1.8.2 结构化语义 Lane 与 AnswerContract

> 文档版本：`1.10`。
> 状态：`Active`。
> 生效日期：`2026-07-30`。
> 替代关系：接受 ADR-0009；替代 09 中关键词/正则 Lane 和 Lane 内 fallback，其他 Release、Snapshot、Evidence、ActionGateway、Citation 与 Cost 契约继续有效。

## 当前批准的执行顺序

```text
自然语言及可见会话上下文
→ 一次 Flash 语义 Router
→ 严格 LaneDecision Schema
→ 确定性 Lane 权限
→ Lane 内 Published Agent
→ CapabilityDecision
→ AnswerContract
→ 受控生成或执行
→ 结构化事实门禁
→ Trace / RunEvidenceLedger
```

Lane 为 A 安全协同、B 物业受控、C 隔离通用与 CLARIFY 澄清。无法判断进入 CLARIFY，不默认进入 B。A 和 CLARIFY 不选择业务 Agent；B/C 目标必须属于当次 Snapshot 中对应 `domain_scope`。

## 结构化合同

`LaneDecision` 保存 Lane、稳定意图、原因码与中文原因、置信度、是否澄清、请求类型、允许域和目标 Agent。`AnswerContract` 保存回答模式、Evidence 要求、Skill/RAG/Tool/write/handoff 权限、禁止声明和决策理由。

Lane、request_kind 与 response_mode 必须正交：Lane 表达领域/权限，request_kind 表达用户任务，response_mode 表达执行方式。C 允许 `fact`，C + fact/general 均映射为 `safe_general`；B + fact 映射为 `grounded_answer` 并要求当次合法 Evidence。B/C 的 unsafe_request 均为 `safe_refusal`，但不改变各自领域边界。

回答模式只允许：安全协同、澄清、依据回答、实时读取、受控写入、隔离通用与安全拒绝。物业事实没有合法 Evidence 时不得生成能力、流程、地点、时效或已执行动作；实时事实只认本轮成功 Tool；写入成功只认 Receipt。

## 上下文、失败与证据

- Router 仅接收用户可见成功历史；Router Prompt、JSON、原因和候选集不进入垂直 Agent。
- Schema、Provider 或 Lane 目标校验失败时受控失败，不 fallback、不自动重试。
- 每次真实 Provider 请求继续逐条进入 `model_calls`、三类 Provider Usage 与成本账本。
- LaneDecision、AnswerContract 与 CapabilityDecision 同一 Trace 持久化并供页面解释。

## 不变边界

不新增数据库表、依赖、队列或能力配置；RuntimeRelease 保持 v27；历史数据不回填；动态 Published Agent 仍通过 Snapshot 元数据进入 Lane 内候选集。

## 回滚

普通 revert Fix2 实现提交后仅重建 API/Web；历史 Trace、会话 Snapshot、业务数据和 RuntimeRelease 不改写。
