# 10｜V1.8.2 最终三分类 Lane 与执行边界

> 文档版本：`1.11`。
> 状态：`Active`。
> 生效日期：`2026-07-30`。
> 替代关系：接受 ADR-0010；替代 ADR-0009 的 CLARIFY Lane、复合字段矩阵与 Router 内 Agent 选择，其他 Release、Snapshot、Evidence、ActionGateway、Citation 与 Cost 契约继续有效。

## 当前批准的执行顺序

```text
当前用户消息 + 用户可见成功对话历史
→ 一次 Flash 语义 Router
→ A危险 / B物业 / C其他
→ 固定 Lane 权限
→ Lane 内 Agent 选择
→ CapabilityDecision / AnswerContract
→ 受控回答或执行
→ 结构化事实门禁
→ Trace / RunEvidenceLedger
```

Router 只保存 Lane、一句中文理由和简短业务意图。Lane 有效性只由 A/B/C 枚举决定；请求类型、目标 Agent、置信度、允许域、回答模式和 Agent 选择结果都属于下游解释，缺失或失败不能反向否定 Lane。

## 三条固定 Lane

- A：明确现实危险。立即给出简短安全提示并 Handoff；普通 Agent、Skill、RAG、MCP/Tool 和 ActionGateway 全部跳过，用户的“不转人工”不能覆盖。
- B：明确需要物业回答、查询、办理或协助。只允许 `property` Agent；物业制度、价格、时效、权限和流程必须来自当次有效 Skill 或采用的 RAG，实时状态只认成功 Tool，写入只认确认后的 ActionGateway 与 Receipt。
- C：其他全部，包括非物业、信息不足和暂时无法判断。只允许 `isolated_general` Agent；全部物业能力跳过。没有合适 Agent 时礼貌说明能力有限，不能跨域补位，也不能把 Agent 缺失统计为 Lane 错误。

系统不再设置 CLARIFY Lane。用户补充信息时，下一轮重新结合可见前文分类；上一轮 Lane 不绑定下一轮。

## 上下文与状态机边界

Router 只能看到当前消息和用户可见的成功对话历史；历史 Router JSON、内部分类、Trace、内部 Prompt、Tool 调试信息和控制字段不得进入 Router 或业务回答。

已进入报修资料收集、等待业主确认等明确流程时，补充资料、确认和取消继续该结构化流程；用户明确更换话题后重新分流。该例外依据已持久化业务状态，不依据关键词或默认 Lane。

## Agent 与证据

A 不选普通 Agent。B/C 的 Agent 选择发生在 Lane 之后，只能在当次 Snapshot 的同域 Published Agent 内进行；同域唯一 Agent 可直接选择，缺失或选择失败形成可见下游边界。Lane、Agent 选择、能力命中和执行结果在评估中分别统计。

Provider 每次真实请求继续逐条落入 `model_calls`、三类 Provider Usage 和成本账本。LaneDecision、AnswerContract、CapabilityDecision 与下游选择状态继续进入同一 Trace 和 RunEvidenceLedger。旧 Trace 不回填、不改写。

## 不变边界

生产 Lane 分类不使用关键词、正则、业务白名单、默认 B 或测试题专用分支；不新增数据库表、依赖、队列或能力配置；RuntimeRelease 保持 v27。
