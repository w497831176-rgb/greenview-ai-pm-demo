# V1.8.2-S10-F Trace truthfulness and budget fail-closed

Date: 2026-08-02

## Scope

- Keep the existing Asia/Shanghai timepoint reporting and Provider-attempt ledger.
- Surface invalid timestamps, unconfirmed sends, orphaned attempts, Provider Usage inconsistencies, missing platform price snapshots, and unavailable Usage as explicit data-quality evidence.
- Count only confirmed outbound Provider attempts in request and Token totals.
- Make `statistics_status=consistent` possible only when range, request counts, and data quality all agree.
- Derive the Reasoning/Output subset relationship from recorded Provider data.
- Fail closed for every optional paid background capability when budget evidence is unavailable.
- Keep ordinary owner consultation outside this optional-background budget gate.

## S10-F audit rework

### P1-1: incomplete Provider actual Usage

- A confirmed outbound attempt with `usage_status=provider_actual` still counts as one Provider request even when Hit, Miss, Output, or Total is absent.
- Preserve every Provider field actually received; do not fill a missing core field with zero or an estimate.
- Classify the attempt as `provider_actual_usage_incomplete`, set data quality to error, keep complete cost unavailable, and make the background budget ledger unavailable.
- A present Total alone is not complete three-part Provider Usage and cannot make the report consistent.

### P1-2: timestamps outside the reporting contract

- A null, invalid, or unparseable `created_at` is excluded from all normal date-range, history-total, distribution, trend, and Trace-detail summaries.
- Keep the attempt as locatable anomaly evidence with `invalid_timestamp_range_unassignable` and `included_in_provider_summary=false`; do not rewrite the historical record or place it in an `unknown` trend bucket.
- Date-scoped and unscoped reports share the same Provider-attempt inclusion contract.

### P1-3: one optional-background budget gate

The shared gate now covers these administrator-triggered Provider surfaces before model construction or invocation:

- Badcase AI classification, Darwin suggestions, Evaluation real runs, and model A/B tests.
- Badcase automatic knowledge extraction (manual-content save remains ungated), model-switch retry, real-chain retest, and AI tool inspection.
- AgentOS direct agent/workflow start, continue, and resume HTTP surfaces have no frontend or internal product consumer, so they return a stable HTTP 410 before AgentOS dispatch. The product uses the audited `/api` capabilities instead. Ordinary `/api/chat/stream` owner consultation remains outside the optional-background gate.
- Generic AgentOS `/eval-runs` and `/optimize-memories` model surfaces are not YIAI product capabilities and return a stable HTTP 410 without querying the budget ledger. YIAI's own Evaluation path remains available through its audited API.

`budget_status=unavailable` returns HTTP 503; a confirmed hard-budget limit returns HTTP 403. A blocked operation creates no Provider attempt and does not advance the Badcase lifecycle.

## Compatibility cleanup

- `provider_usage_inconsistency_reasons` is the canonical field name. Readers remain compatible with historical `provider_usage_inconsistent_reasons` evidence.
- When cost completeness or data quality is not normal, daily/monthly budget percentages and normal alerts remain unavailable. A known partial amount may be shown only as a known partial amount.
- Non-integer historical Token fields and invalid estimated amounts are retained as raw evidence, classified explicitly, and never coerced to zero or allowed to raise a reporting 500.
- A confirmed request with no Provider request ID is `provider_request_id_unavailable`; duplicate IDs or conflicting IDs are hard data-quality errors. These attempts remain counted as sent requests but make reconciliation and the optional-background budget ledger unavailable.
- Provider request ID uniqueness is checked against the full ledger, so a cross-Trace or cross-date duplicate cannot look unique inside a single-day card. Distinct valid ID candidates inside one row are an identity conflict.
- A missing Provider response model is shown as `actual_model_unverified`; conflicting actual-model candidates are `actual_model_conflict`; the requested model never impersonates Provider actual evidence.
- A `provider_attempt` with confirmed sent evidence remains in request totals even if its aggregate flag/stage/status is contradictory, and the contradiction is a data-quality error. A logical/legacy row that nevertheless claims sent evidence stays excluded from normal totals but enters the separate misclassification anomaly bucket.
- Historical `NaN`/`Infinity` values are returned as explicit `invalid_non_finite_number:*` evidence markers, never as zero, and can no longer make Trace detail fail JSON serialization.
- Malformed historical inconsistency-reason collections, grouping labels, requested models, and cost-contract objects are converted into explicit anomaly/evidence codes before arithmetic or response serialization; they cannot produce a reporting 500.
## S10-F monitoring rework

- The fixed-history verifier no longer imports the S10-F test harness. Before any `app` or `db` import it forcibly replaces inherited `PROPERTY_DATA_DIR` with a fresh temporary directory, blocks `init_db`, and rejects production/test-data path overlap.
- The verified ledger is opened only with SQLite URI `mode=ro` plus `PRAGMA query_only=ON`; database, journal, WAL and SHM fingerprints must remain unchanged.
- WorkflowFactory and AgentFactory construction no longer queries the background budget ledger, so Agno read-only run history cannot be blocked by a budget-data incident.
- `RuntimeWorkflowInput` accepts the empty factory input used by Agno history GETs, and snapshot resolution is deferred to the executing step instead of running during factory reconstruction.
- Every blocked background HTTP alias and blocked Workflow Provider step is checked against both the budget fixture ledger and the real temporary `property_db` Provider-attempt ledger, so zero-attempt evidence cannot pass against the wrong database.
- Trace advanced evidence renders all physical Provider attempts, including excluded and unresolved attempts. Complete Usage requires the explicit backend completeness flag; raw partial fields remain visible, and the Reasoning/Output relationship is rendered from each attempt's values instead of being assumed.
- Provider-capable Workflow steps retain their immediate pre-invocation budget gate. The deterministic `extension_acceptance` step contains no budget gate.
- The unused AgentOS direct-run MIME/body classifier was removed together with its second form-parser contract; all direct Agent/Workflow execution POSTs are stable 410.
