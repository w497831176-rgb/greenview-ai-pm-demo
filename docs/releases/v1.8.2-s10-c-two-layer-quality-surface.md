## 修改前 → 修改后

- Evaluation：人工创建入口藏在高级管理、表单技术必填较多、实际回答和节点命中不突出 → 默认可见“人工创建用例”，最少填写名称、用户问题和预期表达；详情按“预期 → 实际 → 能力节点 x/y → PASS/FAIL”展示，Trace、Release、历次运行和逐节点审计折叠保留。
- Badcase：列表缺少人工创建入口、默认展示六段技术处理说明、操作入口与处理路径不直观 → 默认可见“人工创建 Badcase”，详情按“发现问题 → AI 根因建议 → 人工确认修复方案 → 单例复测与人工关闭”展示；AI/Darwin 仍只能建议，草稿、Trace、Release、历次复测和审计全部保留。
- RuntimeRelease：当前、Draft、历史同时展开 → 默认突出唯一当前生效版本、发布时间和 Agent/Skill/RAG/只读 MCP 数量；Draft 单独解释，历史与 Diff 折叠但版本治理、比较和回滚能力不删除。
- Chat：消息气泡下的动态“Trace 用量待核验”文案 → 中性动作“查看 Trace”；用量真伪仍在 Trace 内按 Provider 证据判断。
- Provider 证据：Agno 流式 usage-only chunk 可能缺少已解析的 request id，最终 usage 会落入另一条无 ID 记录 → 从同一原始 Provider chunk 补录原始响应 ID，使内容 chunk 与 `[DONE]` 前 usage chunk 按请求归并；不估算、不补调模型、不把缺失值写成 0。

## DeepSeek 请求审计

- 所有业务调用都通过 `app.settings.build_model()` 返回 `EvidenceDeepSeek`；`app/` 与 `agents/` 没有直接 `chat.completions.create` 或额外 `DeepSeek(...)` 绕行。
- 垂直 Agent 使用流式输出；Router、Badcase AI 分类/Darwin、模型 A/B 为显式非流式调用。
- 固定依赖 Agno 2.6.21 的 OpenAI-compatible 流式适配器会显式设置 `stream_options.include_usage=true` 并迭代 SDK SSE 直到结束；项目在普通响应和每个流式 delta 上捕获 Provider 原始证据。
- 逐请求持久化字段包括 Provider request id、Provider 返回的实际模型、Thinking 状态、cache-hit input、cache-miss input、output、reasoning 和 total token。任一成本必要拆分缺失时保持 unavailable，不显示 `¥0`。
- Provider API 返回的 usage 是该请求的实际用量证据；平台 Trace 不是供应商账单。供应商控制台导出按 API Key / 日期对账，粒度不保证与单条业务 Trace 一一对应。
- 历史请求若没有保留原始 Provider 返回证据，不能追补为“真实 usage”；只能诚实保留缺失状态。

## 人工演示路径

### Evaluation

1. 平台管理 → Evaluation / Golden Set → 人工创建用例。
2. 填写用例名称、用户会怎么问、预期结果至少包含；保存不会调用模型。
3. 打开用例，先点击“启用用例”；需要真实证据时再点击“运行真实链路”并确认一次 Flash 成本。
4. 主层查看预期、实际、能力节点命中 x/y 与 PASS/FAIL；高级证据展开 Trace、RuntimeRelease、历次运行和逐节点判定。

### Badcase

1. 平台管理 → Badcase → 人工创建 Badcase。
2. 填写问题标题和发现了什么问题；保存只登记待处理记录。
3. 详情按四步推进：人工分类；按需请求 AI/Darwin 建议；人工审核并应用修复草稿；人工发起单例复测。
4. 复测通过后由人工记录观察并关闭。AI/Darwin 不会确认根因、应用修复或关闭问题。
