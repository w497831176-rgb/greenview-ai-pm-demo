# V1.8.2-S10-E｜Trace 与成本时间范围统计修复

日期：2026-08-02

## 产品目标

“Trace 分组”和“Provider 请求”是两个数量：前者是一组业务或后台操作，后者是
这组操作里真实发往 DeepSeek 的逐请求 attempt。选择今天、昨天或自定义日期时，
顶部汇总、阶段汇总和 Trace 卡片必须使用同一个 Asia/Shanghai 时间范围及同一组
Provider attempt。

## 根因与修复

Provider attempt 使用带 offset 的 ISO 时间，历史聊天 Trace 使用无 offset 的北京
时间空格格式。旧查询让 SQLite 直接比较 TEXT，导致同一真实日期的数据被错误
排除，model-only 后台任务也会遗漏。

本阶段不迁移、不回填、不改写历史数据，只在报表查询层完成：

- 带 offset ISO 按其 offset 转为 UTC 时间点；
- 无 offset 历史时间明确解释为 Asia/Shanghai；
- 日期结束边界覆盖当天最后一微秒；
- 趋势的小时/日期标签也先换算为 Asia/Shanghai 再分桶，不截取原始 ISO 文本；
- Overview、阶段汇总、Trace 分组和卡片共同复用严格 Provider attempt 口径；
- 跨午夜 Trace 仍是一组，但卡片只汇总所选范围内的请求；
- Evaluation、Darwin、Badcase AI 操作等 model-only Trace 进入调用记录，并展示
  后台任务类型；
- 三类核心 Token 与 Reasoning 分开汇总，Reasoning 明确是 Output 子集且不重复
  计入 Total；缺失的 Reasoning 不显示为 0；
- 接口同时返回 `trace_group_count` 与 `provider_request_count`，前端分别展示；
- 顶部与列表范围或 Provider 请求数不一致时显示“统计口径异常”；
- Overview、Trace、价格或预算接口失败时显示加载失败，不伪装为 0 次、¥0 或
  “不适用”。

## 确定性验证

主合同：

```text
python scripts/test_v182_s9b2_time_pagination.py
```

覆盖空格时间、`+08:00`、`Z`、跨北京时间日期、日末微秒、model-only、跨午夜
Trace、范围外模型/阶段不误命中、Evaluation/Badcase/Darwin 后台任务类型、昨天/
自定义范围、两类计数、Reasoning 不重复计数、口径异常和接口失败展示。继续回归
S9-B、S10-D Provider 逐请求合同及相关成本/前端合同。全部测试均使用临时数据库
或静态源码，不调用模型。
