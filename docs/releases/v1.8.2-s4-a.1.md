# V1.8.2-S4-A.1：历史 Release 差异可视化修正

状态：候选实现完成，待测试、Git 固化与 NAS Web-only 部署  
复杂度：S  
范围：历史 RuntimeRelease Diff 的前端信息层级与可读性

## 用户可见问题

S4-A 已经提供确定性历史 Diff，但详情放在约 448px 的全局 Drawer 中。桌面两列
对比在该宽度内仍会退化为上下排列；修改前、修改后缺少固定列标题；历史入口只写
“查看变更”，用户必须自行判断比较对象。统计卡片和工程配置还会先于 Agent 主线
占据注意力。

## 最小修正

- 历史 Diff 改为独立 `max-w-6xl` 大尺寸 Modal；完整原始快照继续使用 Drawer；
- 标题固定展示 `Release #父版本 → Release #当前版本`；
- 同时展示两个 Release ID、发布时间和当前运行标识；
- 根据真实 Diff 在前端确定性拼装一句话变更结论，不调用模型；
- Agent 作为第一层主卡片，字段使用“变更项 / 修改前 / 修改后”三列表格；
- Prompt 默认只展示前三行与有限长度，点击后展开完整文本；
- Skill、RAG、MCP 挂载明确拆为“新增能力”和“移除能力”；
- 其他工程配置移动到 Agent 之后，并默认折叠；
- 重复快照、初始版本、新增对象和删除对象都有明确占位状态；
- 历史 Diff 仍只在点击时请求，不改变 Overview 首屏接口。

## 明确未改

没有修改 RuntimeRelease 数据结构、Diff 算法、API、数据库、平台配置、历史数据、
Agent/Skill/RAG/MCP、S1/S2/S3 或 S4 动态能力；没有调用真实模型或使用浏览器
自动化。
