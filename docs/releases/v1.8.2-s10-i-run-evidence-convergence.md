## 修改前

- 复合问题用整条消息给 RAG 分片统一评分，Tool 子任务和控制说明会稀释命名文档知识子句；显式命名文档也没有覆盖名额。

## 修改后

- 新增不可变 `RunEvidenceBundle`，统一保存本轮合格 RAG Snapshot、Skill 证据、成功只读 `ToolEvidence`、committed Receipt、验证/交付的 evidence ID、Tool 事实链接及拦截原因，并复用现有 Evidence Ledger JSON 持久化，无数据库迁移。
- RAG 使用由当前 Snapshot 文档目录和 Agent 绑定范围生成的确定性子句计划。命名文档子句只在精确文档范围内评分，并为通过既有 0.2 内容门槛的显式命名文档保留覆盖名额；`top_k=5` 与阈值未放宽。
- MCP 两条只读执行路径共用中央结果冻结函数：从未截断结构化结果生成 payload hash、安全 JSON path facts、规范值和通用单位；调用参数与失败结果不构成证据，500 字符摘要仅用于展示。
- Renderer 以同一原子事实范围校验 RAG 与 Tool：每个引用标记分别判定，结构化数值必须由同一 JSON 父对象中的字段语义、定位事实、规范值和单位共同支持，不能跨字段、跨对象或跨引用借证。
- Agent 可见依据、Citation Renderer、最终采用判定与 Trace 投影都消费同一 Bundle。后端直接输出 retrieved/adopted/unused/tool links/withheld/violation；前端不再从 assistant citations 猜候选。
- 历史 Ledger 不改写。旧 Trace 若能从当次成功 Tool 结果明确证明是旧校验器未识别结构化数值，只读投影会显示精确原因；无法证明时保留原原因。
