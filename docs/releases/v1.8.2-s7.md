## 目标

本阶段只完成两个相互关联的演示目标：用真实 Badcase #677 走完一次 Evaluation 失败修复闭环；把 Badcase 库改为服务端分页、轻量列表和产品人员可读详情。目标①②及 S5 成本底座保持冻结。

## 已确认的原始失败

- Evaluation Case #2：`请问小区是否提供免费搬家服务？请告诉我专用预约号码、服务时段、免费额度和办理步骤。请只使用知识库直接证据；没有证据就明确说依据不足，不要猜测，也不要转人工。`
- 原 Evaluation Run：#2，结果 failed。
- 原 Trace：`1098e350a28e4e11`。
- 自动 Badcase：#677。
- 回答安全性：PASS；系统没有证据时安全拒答，没有伪造 Citation、MCP 或业务写入。
- Agent 选择准确性：FAIL；实际错误命中 `mars-greenhouse-agent`，预期为 `customer_service`。
- 直接根因：Agent #74 的 description 与 instructions 同时参与动态路由词提取，原配置中的“使用、知识库、直接、证据不足、猜测、专用”等通用短词与 Case #2 文本重叠。仅改 description 仍会被 instructions 中通用词误触发，因此最小修复必须同时收窄这两个路由配置文本；不修改 Router 代码。

## 工程修改

- Badcase 列表改为真正的服务端分页：默认 20 条，可选 50 条；返回 `items/total/page/page_size/total_pages`。
- 列表 SELECT 只返回 ID、状态、来源、优先级、分类、根因域、摘要、Trace、时间和 Darwin/草稿/复测布尔标记；不加载完整回答、Darwin、Prompt、草稿或 JSON。
- 保留状态、来源、分类、根因域、优先级、关键词、Trace、复测和日期筛选；COUNT 与分页 SELECT 各一次，无逐条详情 N+1。
- 详情默认按“问题概览 → 根因结论 → 解决方案与人工决策 → 验证与发布 → 生命周期时间线”展示；完整 JSON、Darwin 和动作原文放入默认收起的技术证据区。
- 新增 Badcase 内的最小审计动作：验证已有 Agent 管理 API 的实际修改结果并记录“人工审核后应用 Agent 路由配置”，同时确认 Skill/RAG/MCP 绑定未变化。
- Evaluation 单用例运行可显式关联原 Badcase；PASS 或失败都写入同一个 Badcase 的复测证据，原失败 Run 不改写，失败时不另建重复 Badcase。
- Evaluation 概览同时展示“累计运行历史”和“每个用例最新结果”，避免把历史 5/6 与当前 5/5 混为一谈。
- 未新增数据库表或字段。
