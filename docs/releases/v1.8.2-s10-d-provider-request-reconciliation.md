# V1.8.2-S10-D｜DeepSeek Provider 逐请求对账闭环

日期：2026-08-01

## 目标与边界

本发布只加强运行证据，不改变 Router、三车道、Skill/RAG/MCP、HITL、
ActionGateway 或 RuntimeRelease 能力配置。因此继续使用当前 Published
RuntimeRelease，不生成空版本。

Provider request 是 Token 与平台直接成本的最小单位。业务阶段、一次对话、
Evaluation、Badcase 复测和预算拦截只能引用或聚合底层请求，不能冒充请求。

## 修改前 → 修改后

- 请求完成后由 Router、Selector、Badcase、A/B 等业务代码手工补 ModelCall
  → `EvidenceDeepSeek` 在四个 SDK 出口发送前自动建立 durable attempt，返回、
  异常或取消后更新同一行。
- 模型实例共享 journal，消费时全量清空 → `ContextVar` 隔离每个 Trace/Task，
  content 与 usage-only chunk 只归并到当前 attempt。
- 后续 `None` 或部分 usage 可覆盖完整值 → 递归按非空字段合并，Provider 原值
  保留；不一致只标记，不偷偷修数。
- OpenAI-compatible SDK 隐藏重试不可见 → `max_retries=0`；显式重试每次重新
  进入中央入口并获得独立 attempt。
- Badcase 提取知识、切换模型重试、检查工具漏记 → 全部通过中央入口自动记账。
- Badcase 复测额外写 `stage=retest` ModelCall → 复测仅保存 logical aggregate 和
  底层 Trace 引用，不进入 Provider 请求、Token 或成本汇总。
- Usage 缺失可能笼统显示或被算成 0 → 保存具体状态、阶段、完成证据与原因码；
  Token/金额保持不可得。正常耗尽但 Usage 缺失会创建待人工处理 Badcase。
- `estimated_cost_cny` 语义含混 → 新记录明确
  `token_source=provider_actual`、`cost_source=platform_price_snapshot`、
  `cost_disclaimer=platform_price_snapshot_not_provider_final_bill`。

## 统一记账位置

所有源码内的 DeepSeek 模型都由 `app.settings.build_model()` 创建为
`EvidenceDeepSeek`。中央边界覆盖：

- `invoke`
- `ainvoke`
- `invoke_stream`
- `ainvoke_stream`

业务入口与中央位置：

| 入口 | 业务调用 | Provider 记账 |
|---|---|---|
| Semantic Router | `agents.router.classify_lane_decision` | `EvidenceDeepSeek.ainvoke` |
| Agent Selector | `agents.router.select_lane_agent` | `EvidenceDeepSeek.ainvoke` |
| Vertical Agent | `Agent.arun(stream=True)` | `EvidenceDeepSeek.ainvoke_stream` |
| Tool 循环 | Agno 每轮模型调用 | 每轮重新进入 `ainvoke_stream` |
| Evaluation | canonical chat runtime | 引用 Router/Selector/Vertical attempts |
| Badcase AI 分类 | `_llm_generate` | `EvidenceDeepSeek.ainvoke` |
| Badcase 提取知识 | `_llm_generate` | `EvidenceDeepSeek.ainvoke` |
| Darwin 建议 | `_llm_generate` | `EvidenceDeepSeek.ainvoke` |
| Badcase 切模重试 | `_llm_generate` | 独立显式 retry attempt |
| Badcase 检查工具 | `_llm_generate` | `EvidenceDeepSeek.ainvoke` |
| Badcase 复测 | canonical chat runtime | 只引用底层 attempts，无 retest Provider 行 |
| 模型 A/B | 两个并发 `_run_model` | 两个 ContextVar scope，各自逐请求记账 |
| AgentOS 直接 Agent | runtime agent factory | 中央 fallback 使用 run/session identity |
| AgentOS Workflow | canonical coordinator | 引用 canonical attempts |
| 旧 Router callable | `classify_intent` | 即使未来调用也由中央 fallback 记账 |
| 明确转人工短路 | 无模型调用 | 0 Provider attempt，成本不适用 |

源码中没有额外 `OpenAI/AsyncOpenAI`、`chat.completions.create` 或直接
DeepSeek HTTP 绕行。

## 数据与兼容

为保证“付费请求前落 pending”和并发唯一性，现有 `model_calls` 只增加六个
nullable 字段：`local_attempt_id`、`provider_request_id`、`record_kind`、
`usage_status`、`cost_source`、`finished_at`，并为两个 ID 增加非空 partial
unique index。详细证据仍存现有 `usage_normalized` JSON。

迁移不回填、不改写、不删除历史行。历史缺失 Usage 没有原始 Provider 返回证据，
不能追补为 `provider_actual`。

## Usage 与成本口径

- 三类计费 Token：cache-hit input、cache-miss input、output。
- `reasoning_tokens` 是 output 子集，只展示，不重复加总。
- 校验：`total = hit + miss + output`，以及 `input = hit + miss`。
- Provider 字段不一致时保留原值，并设置 `provider_usage_inconsistent` 和原因列表。
- 人民币直接成本只在三类 Token 完整时，按当次平台冻结价格快照计算。
- 该金额不是 DeepSeek 最终账单；优惠、舍入、统计延迟、价格生效窗和时区边界
  均可能造成供应商控制台金额差异。

## DeepSeek 官方依据

- Chat Completion 文档要求流式请求设置 `stream=true`；
  `stream_options.include_usage=true` 时，会在 `[DONE]` 前返回额外 usage chunk，
  其他 chunk 的 usage 为 null，同一流的 chunk ID 相同。
- 文档定义 `prompt_tokens = cache-hit + cache-miss`，
  `total_tokens = prompt + completion`，reasoning 属于 completion 明细。
- Token 文档说明单次真实处理量以模型返回的 usage 为准。
- Pricing 文档说明金额按 Token 数量乘价格，且官方价格会变化。
- 官方 FAQ 只说明按月份导出并在 amount CSV 中按 API Key 拆分；未文档化
  可供平台调用的请求级账单导出接口。

该脚本使用临时数据库和合成 Provider 证据，不调用付费模型。覆盖 chunk 归并、
raw ID、None 防覆盖、无 Usage 正常结束、流中断、并发隔离、显式重试、Tool
循环、三个 Badcase 漏记入口、复测不重复、转人工零请求、落库失败、reasoning

## 控制台对账

平台可验证“按 Provider 响应逐请求保存”。DeepSeek 控制台同期聚合必须由用户
按同一 API Key、同一开始/结束时间、同一 UTC+8 时区手工核验；在用户完成前，
供应商控制台对账状态保持 `PENDING_USER_VERIFICATION`，不得宣称逐请求账单已
100% 对上。

## 回滚

代码回滚使用本发布 Git commit 的普通 `git revert`，随后仅重建 API/Web。
六个 nullable 列及索引可安全保留；不需要删除数据库、Volume、Trace、Badcase、
Evaluation、Release 或业务数据，也不得改写本发布后产生的 Provider evidence。
