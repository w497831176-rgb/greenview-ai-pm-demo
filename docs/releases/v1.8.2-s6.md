## 用户可见能力

### 1. 反馈入口

- 👍 可不填写原因；保存为正向反馈，不创建 Badcase。
- 👎 原因可选；未填写时保存明确默认值“未提供具体原因”。
- 负向反馈关联原始会话、用户消息、AI 回答、回答消息和 Trace，并创建或复用唯一 Badcase。
- 同一回答重复提交相同反馈返回幂等结果；不会重复创建 Badcase；相反反馈返回冲突。
- 前端原因统一为：答非所问、事实错误、无依据编造、未解决问题、其他。
- 提交成功后消息卡显示“已点赞”或“已反馈 · Badcase #ID”，并禁用重复点击。

### 2. Golden Set

- 沿用 Evaluation Case / Run、Trace、RunEvidenceLedger、`model_calls` 和 Badcase。
- 用例可以确定性检查 Agent、Skill、RAG、Tool/MCP、Citation、Handoff、模型调用次数和业务副作用。
- 每条断言保存预期、实际、PASS/FAIL 与失败说明。
- 失败运行自动且幂等地创建 `source=evaluation` Badcase，通过 Eval Run 的 `badcase_id` 反向关联，并在 Badcase 上下文保存 case、run、trace、回答、失败断言和运行证据。
- Provider 或运行时失败只能得到 FAIL，不会保存为 PASS。
- 受控失败探针有独立标记，并从黄金集用例数、运行数、通过率和成本统计中排除。
