# V1.8.2-S4-A：RuntimeRelease 发布中心精简与版本差异

状态：代码、测试、Git、NAS 部署与性能测量已完成；人工 UI 体验待用户验收  
复杂度：M  
范围：发布中心首屏、确定性配置 Diff、轻量历史摘要、重复发布阻断

## 用户可见问题

原发布页首屏同时请求当前完整快照、最多 50 个历史完整快照、验收案例和
验收记录。NAS 基线实测四个接口合计约 6.8 MB，其中历史 Release 为
6,747,884 bytes；页面还会把 Trace、组合验收和新增能力验收默认放在发布主流程。

“仅校验草稿”原来会持久化一条 draft；配置完全相同时仍可能生成重复 Release。
历史页面只能看到能力总数，无法解释具体 Agent 参数和挂载能力变化。

## 最小改造

- 首屏只请求一个轻量 overview，不返回完整 config、Chunk、Skill 正文、完整
  Agent Prompt 或 MCP Schema；
- Draft 与 Published 的 Diff 在内存中确定性计算，不新增数据库或表；
- 展示 Agent 名称、描述、Prompt、模型、状态、类型及 Skill/RAG/MCP 绑定变化；
- Skill、知识文档、MCP Server/Tool、模型、检索和预算策略只展示变化项；
- 完整 Prompt、历史 Diff 和不可变配置快照按点击加载；
- 高级验收改为二级视图，首屏不请求验收案例和运行记录；
- 预览和无变化发布不写 RuntimeRelease；
- 发布事务拒绝与当前 Published 相同的 config hash；
- 保留不可变快照、parent_release、新会话生效、旧会话 Snapshot 和回滚机制。
