# V1.8.2-S4-A.2：受控业务写入证据表达修正

状态：功能与确定性合同完成；Git/NAS 证据以本次交付报告为准；人工 UI 体验待用户验收  
复杂度：S  
范围：维修工单受控写入在会话消息与 Trace 中的前端证据表达

## 用户可见问题

已有运行时会把 `ActionProposal → 业主确认 → ActionGateway → ActionReceipt`
闭环保存为真实证据，但前端把 `action_gateway` 与普通工具混在“已调用工具”标签中；
无模型的确定性工作流显示为“Trace · 不适用”；Trace 详情也只识别旧名称
`work_order_workflow`。结果是用户看不出这是应用内部受控写入、是否经过业主确认、
是否真的产生写入回执，以及它与 MCP、模型、转人工分别是什么关系。

## 最小修正

- `action_gateway + work_order.create` 在消息卡片中显示为
  “受控业务写入：创建维修工单”，不再伪装成普通 Tool 或 MCP；
- 明确执行通道为“业务规则 → ActionGateway → 内部工单服务”；
- 只有 `committed` 且同时存在 `receipt_id`、`resource_id` 时才显示正式提交成功；
- 成功卡片展示真实工单号、写入回执、提议编号、业主确认（HITL）与幂等保护；
- 草稿、等待确认、阻断、取消、失败和重复确认使用可读状态，避免一律显示成功；
- 无模型的工单规则工作流显示“Trace · 规则工作流”，说明模型 Token/成本不适用，
  但业务 Trace、确认和写入审计仍有效；
- Trace 同时兼容 `action_gateway` 与历史 `work_order_workflow`；
- 新增“受控业务写入证据”区，按已有证据展示
  Draft → Proposal → Owner Approval → ActionGateway Execution → Committed Receipt；
- Trace 明确说明正式写入由内部工单服务完成，没有调用 MCP，也没有模型写入；
- 不展示完整 Proposal Payload，Trace 中的手机号码默认脱敏；
- 普通 MCP、RAG、模型调用和 Provider 用量标签保持原有展示逻辑。

## 明确未改

没有修改后端、ActionGateway、工单写入架构、MCP、数据库、业务数据、RuntimeRelease、
RAG、Agent/Skill 配置、S1/S2/S3 或 S4 动态能力；没有调用真实模型、创建工单、
运行 Playwright 或浏览器自动化。
